# P0 批量选片与资源准入规格

> 状态：Approved for execution
>
> 日期：2026-07-12
>
> 前提：保留当前 P0 主流程、自由裁切和既有 Blob URL / generation 所有权规则。

## 1. 目标

让用户在本地暗房中先完成选片，再把明确入选的照片送入单张冲洗、长条拼合和 ZIP 导出；在浏览器分配高成本解码、Canvas 或 ZIP 内存前，给出基于整批像素与输出规模的可理解预检。

这解决两个当前阻塞问题：

- `processAll`、长条和 ZIP 默认覆盖整卷，用户无法排除废片或仅交付精选。
- 当前只针对单张文件大小与最长边提示风险，无法提前发现整卷解码内存、长条 Canvas 或 ZIP 打包会超出安全边界。

## 2. 用户与范围

目标用户是一次导入多张扫描图或手机照片、需要挑选并导出部分成片的摄影用户。

本 P0 包含：

1. 每张照片的会话内“入选 / 未入选”状态，导入时默认为入选。
2. 接触印象和长条序列中可见、可键盘操作的单张切换控件，以及“全部入选 / 清空入选”的批量操作。
3. 入选数 / 总数、待冲洗数和受限原因的可见摘要。
4. 单张冲洗、重新冲洗、长条生成、ZIP 导出严格只使用入选子集。
5. 上传后与高成本操作前的批次预检：总解码源像素、预估工作内存、目标 Canvas、当前可导出 ZIP 输入量。
6. 告警与阻断状态中的下一步动作：调整入选、移除大图、切换较低输出质量或取消；绝不静默缩放、压缩或删除照片。

本 P0 不包含：

- HEIC/RAW/动画图片支持、云端上传、持久化选片状态或全局状态库。
- RenderPlan 重写、Worker 取消协议、ZIP 流式实现或素材导出预设。
- 修改顺序规则、帧号规则、渲染 key、Worker 消息协议或 ZIP 文件命名模式。

## 3. 状态契约

### 3.1 图片状态

`ImageItem` 增加以下会话字段：

- `included: boolean`：是否进入本轮批处理，导入值恒为 `true`。
- `sourceWidth` / `sourceHeight`：上传成功解码后记录的自然尺寸，用于准入估算。

这两个字段不写入现有偏好存储。切换 `included` 不得：

- 改变图片顺序、现有 frame number 或单张 render key；
- 释放、失效或重新生成已有成片；
- 改变 EXIF、裁切/旋转 transform 或原始文件。

删除图片仍按现有 URL 回收规则执行。

### 3.2 选片行为

- 新导入照片默认入选，以保持当前“全部处理”的首次行为。
- 卡片和长条序列都能切换单张入选状态；控件必须有可访问名称，未入选状态不能只依赖颜色表达。
- 工作区提供“全部入选”和“清空入选”。处理或导出进行中禁用这些会改变批次范围的操作。
- 入选为零时，主操作不调用渲染器或 ZIP；界面明确提示“请先选择至少一张照片”，并提供“全部入选”。
- 预览、删除、排序与裁切仍可针对未入选照片使用。排序仍是入选子集内的唯一输出顺序来源。

### 3.3 输出范围

| 操作 | 输入集合 | 结果有效性 |
| --- | --- | --- |
| 单张冲洗 | 入选且 `unprocessed/stale/failed`；强制模式也仅限入选 | 未入选卡片不产生新成片 |
| 单张 ZIP | 入选且拥有 current artifact 的顺序子集 | ZIP 序号沿用原卷顺序，不重新编号 render key |
| 连底长条 | 入选的顺序子集 | 长条 key 必须包含入选成员与其顺序，避免“选片变化但旧长条仍显示为当前” |
| 单张下载 | 当前卡片的 current artifact | 保持既有能力，不因未入选而禁止用户单独下载 |

选择变化本身不会使单张成片 stale；但会使长条结果 stale，因为它的输入集合改变。

## 4. 批次资源准入

### 4.1 输入与模型

准入评估必须是无 React / DOM 副作用的纯函数。它使用：

- 入选图片的 `sourceWidth * sourceHeight`，估算解码像素和 RGBA 内存；
- 当前 `processingMode`、frame 模式、输出模式和入选数量，估算单次输出 Canvas / 长条 Canvas；
- 单张 ZIP 的 current artifact Blob 大小，估算 ZIP 读取与组包压力；
- 现有 `renderBudget` 和 `MAX_ZIP_INPUT_BYTES` 限制作为硬边界。

结果至少包含 `ok`、`warning`、`blocked` 三档，以及机器可读 reason、入选数、源像素、估算字节和可向用户展示的建议。阈值必须集中定义并由单元测试覆盖，不能散落在 JSX。

### 4.2 触发点

1. 上传成功后：展示非阻塞批次健康摘要；单张大图 warning 仍保留。
2. 单张批量冲洗前：检查入选集的累计解码 / 工作内存；`blocked` 时不开始任何渲染。
3. 长条生成前：同时检查入选集和目标长条 Canvas；`blocked` 时不调用 `generateFilmStrip`。
4. ZIP 打包前：使用渲染时记录的 Blob 字节数检查仅入选 current artifacts 的 ZIP 输入量；`blocked` 或容量信息缺失时不 fetch Blob、不开始打包。

`warning` 可继续，但必须显式表明风险；`blocked` 必须阻断对应操作，不能在调用渲染器后才用泛化错误提示。

### 4.3 可行动反馈

风险消息用当前上下文说明：例如“已入选 18/36 张，解码约 620 MB”或“长条画布超过浏览器安全上限”。它必须提供至少一个不破坏数据的下一步：

- 取消部分入选；
- 移除最大图片；
- 切换现有预览质量；
- 返回继续整理。

不可自动执行这些动作，也不可承诺精确处理时间或设备无关的内存上限。

## 5. 信息架构与可访问性

- 工具栏 / 会话摘要显示“入选 X / Y”，并在单张 / 长条模式一致。
- 选片控件使用 checkbox 或语义等价的 `aria-pressed` button；名称包含文件名和目标状态。
- 零入选、warning、blocked 通过现有 `aria-live="polite"` 可读；阻断错误使用现有可关闭 dialog，焦点逻辑不退化。
- 桌面和 390px 移动端均不能因新增摘要或操作条产生横向溢出、重叠或低于 44px 的触摸目标。

## 6. 验收标准

1. 导入三张照片后，默认显示 `3 / 3` 入选；取消其中一张后显示 `2 / 3`，现有成片不被删改。
2. 仅入选照片被发送给 `processImage`、`generateFilmStrip`、ZIP 收集；顺序与原卷中相对顺序一致。
3. 零入选时冲洗、长条和 ZIP 都不触发重渲染、fetch 或打包，且有可见恢复操作。
4. 长条在选片变化后显示需重生成，单张 current artifact 不因选片变化而失效。
5. 超过累计源像素 / 长条 Canvas / ZIP 上限时，在昂贵调用之前阻断并说明原因；warning 不阻断。
6. 现有单张、排序、裁切、预览、失败重试、停止后续和下载流程保持通过。
7. 新纯函数有 Vitest 覆盖；桌面与移动端关键路径有 Playwright 覆盖；`npm run check`、`npm run test:e2e`、`git diff --check` 通过。
