# P0 主流程与移动端可靠性规格

> 状态：Approved for execution
>
> 日期：2026-07-12
>
> 前序基线：`e5c5a84`

## 1. 目标

让首次用户和手机用户能够不理解全部参数，也能完成“添加照片 -> 处理 -> 查看 -> 下载”；同时把系统已经具备的异步正确性转化为用户可见的状态、恢复动作和信任信息。

## 2. 子任务 P0-A：任务状态、上传与取消

### 用户问题

- 设置变化后旧结果静默消失，用户不知道需要重新处理。
- 处理过程只有批次文字，没有每张图片的明确状态。
- 大图警告与真正错误共用“出错了”模态。
- `image/*` 接受范围大于实际支持范围，解码失败仍加入列表。
- 用户不能停止后续处理，也无法判断停止后保留了哪些结果。
- ZIP 打包可重复触发且没有独立进度状态。

### 行为规格

1. 上传只接受 JPEG、PNG、WebP；其他类型逐项拒绝。
2. 图片尺寸解码失败时拒绝文件并立即回收已创建的 preview URL。
3. 大图仍可加入，但以非阻塞 warning 展示，不使用错误标题。
4. 每张图片呈现且可被辅助技术读取的状态：`未处理`、`待更新`、`等待中`、`冲洗中`、`已完成`、`失败`。
5. 设置、EXIF、顺序相关帧号或单图变换变化后，旧结果保留为内部资源，但 UI 必须明确标为待更新且不可下载。
6. “停止后续”使当前 generation 失效；已经完成的结果保留，未开始项回到未处理/待更新。允许当前正在执行的 Canvas 工作自然结束，但其晚到结果必须丢弃并回收。
7. 单张批次默认只处理未处理、待更新和失败项；提供显式“重新处理全部”入口。
8. ZIP 打包期间按钮禁用并显示打包状态；并发点击只创建一次任务。
9. 批次结束显示非阻塞摘要：成功数、失败数、是否被停止，以及主要下一步动作。

### 不变量

- generation、image ID、settings key 和 Blob URL 所有权规则不得削弱。
- 部分失败不得删除已完成结果。
- 警告不阻塞继续工作；错误必须给出重试或移除动作。
- 不伪造剩余时间或百分比。

## 3. 子任务 P0-B：移动端与无障碍基础

### 行为规格

1. 小于 `768px` 时工作室位于设置之前；空态首屏必须看见上传入口和本地隐私承诺。
2. 设置在移动端使用可展开面板，不形成独立整屏嵌套滚动。
3. 移动端底部有稳定主操作区，根据状态提供添加、处理/停止、下载。
4. 卡片查看、下载、重试、删除不能依赖 hover；触屏目标不小于 44px。
5. 每张图片提供上移/下移按钮；首项上移和末项下移禁用。保留桌面拖拽，但键盘/触屏有等价路径。
6. 上传区使用真实 button/label 语义，可通过 Enter/Space 激活。
7. 所有 icon-only 控件有 `aria-label`；状态摘要使用 `aria-live="polite"`。
8. 预览、错误和捐赠覆盖层使用 dialog 语义；Escape 可关闭，关闭后焦点恢复到触发器。
9. 支持 `prefers-reduced-motion`，状态变化不依赖动画才能理解。

## 4. 非目标

- 不引入路由、账号、云存储或状态管理框架。
- 不重做全部视觉系统。
- 不在 P0 实现自由裁剪、配方、PWA 或社媒模板。
- 不用 toast 库、拖拽库或无障碍组件大依赖解决局部问题。

## 5. 验收标准

- `390x844` 首屏可见品牌、隐私承诺、上传入口和主要工作区，不需要先滚完整设置栏。
- 仅触屏完成添加、排序、删除、处理、重试、预览和下载。
- 混合上传能逐项说明接受、警告和拒绝原因。
- 设置变化后，所有受影响的旧结果显示“待更新”，不会静默伪装成原图结果。
- 停止批次后不再启动下一张，已完成结果仍可下载。
- 键盘可完成上传、模式切换、排序、处理、预览关闭和下载。
