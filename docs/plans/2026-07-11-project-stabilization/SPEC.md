# FilmFrame 项目稳定化规格

> 状态：Executed
>
> 日期：2026-07-11
>
> 前序基线：`main` / `a036da628e1538573769fc27950c1fee6b33aff6`
>
> 所有者目标：先做顶层项目审查并偿还阻碍后续功能开发的高杠杆技术债。
## 1. 背景

FilmFrame 在审查开始时可以构建并完成核心浏览器端图片处理，但缺少可信的自动测试基线，且主线程与 Worker 存在重复渲染实现。当时的工作区还包含未提交的 Worker、上传、下载和竖图方向改动，因此审查范围纳入了完整工作树，没有通过清理工作区制造“干净基线”。

本轮工作的目的不是进行无边界重构，而是建立可以支撑后续产品开发的正确性、可验证性和维护边界。

## 2. 目标

### G1：完成项目级深度审查

从架构、代码质量、工程保障、性能与风险四个维度审查当前工作树，所有正式 finding 必须具备：

- 精确文件和行号；
- 可复现的触发输入或操作顺序；
- 上游调用者和下游影响；
- 现有保护为何无效；
- 明确的严重级别与修复建议。

### G2：建立真实可执行的测试入口

`npm test` 必须真正执行断言，而不是只运行 TypeScript 编译。保留独立类型检查，并提供单一全量验证入口。

### G3：修复阻碍可信开发的 P0 正确性问题

本轮至少处理经审查确认的以下类别：

1. 测试不执行和当前几何断言失败；
2. 设置变化后旧结果仍被当作当前结果下载；
3. 预览下载原始文件时内容类型与扩展名错配；
4. 处理期间增删、排序、切模式或改设置导致结果覆盖/恢复旧状态；
5. 新增异步任务产生的 Object URL 生命周期不完整。

### G4：定义渲染一致性契约

本轮不要求一次性合并两套 Canvas 引擎，但必须明确并测试主线程与 Worker 共享的行为契约：路由、输出尺寸、帧号、旋转方向、格式和 fallback。

### G5：保持现有用户工作和产品行为可追溯

- 不重置、隐藏、清理或覆盖审计前已有的 tracked/untracked 工作。
- 行为改变必须先有失败测试或明确规格。
- 不在本轮顺手升级大版本依赖、替换框架或增加无关功能。

## 3. 非目标

- 新增胶片类型、裁切编辑器、账号、云存储或后端；
- 全面视觉改版；
- 一次性重写 `App.tsx` 或全部渲染引擎；
- 发布、推送、创建 PR 或部署生产；
- 未经产品标准确认就改变竖图视觉方向、Gold 模板几何或色彩参数；
- 为追求覆盖率而测试随机像素细节。

## 4. 审查范围

包含：

- 所有根入口、配置、manifest 和文档；
- `App.tsx` 与 `types.ts`；
- `services/` 全部源码，包括未跟踪的新 Worker/上传/下载模块；
- `tests/` 全部测试；
- `public/` 的运行时素材与发布内容；
- 当前 `HEAD` 到工作区的完整 diff；
- 构建、测试、浏览器 smoke、依赖与发布面。

排除：

- `.git/` 内部实现；
- `node_modules/` 代码审查，但会检查依赖树状态；
- `dist/` 源码审查，但会检查构建产物内容；
- GitHub issue/PR 和生产平台状态，除非后续单独授权。

## 5. 功能不变量

1. 图片不得上传到业务服务器。
2. 单图失败不得丢失其他图片的成功结果。
3. 图片顺序决定单张处理、帧号、长条和 ZIP 顺序。
4. 下载文件扩展名必须匹配 Blob MIME 或原始文件类型。
5. 旧设置生成的结果不得被无提示当作新设置结果。
6. 删除图片或替换结果后，不再使用的 Object URL 必须回收。
7. Worker 不可用或失败时必须回退主线程，且不能产生悬挂任务。
8. 竖图单张输出方向和长条片窗方向必须由测试锁定。
9. Gold 模板 fallback 链保持可用：分层素材 -> legacy 模板 -> 程序化 renderer。
10. 未完成的异步批次不得覆盖更新后的图片列表。

## 6. 工程约束

- 优先低复杂度、显式状态和小 API。
- 新增依赖必须说明必要性；测试 runner 是允许评估的唯一新依赖类别。
- 纯逻辑优先抽成无 DOM 依赖函数，以便单元测试。
- 不以“大拆组件”代替正确性修复。
- 主线程和 Worker 的重复逻辑先通过契约测试控制，再逐步共享。
- 所有改动必须保持 `npm run build` 成功。

## 7. 验收标准

### 审查验收

- 有四轴评分和按严重度排序的 findings；
- 每个高严重 finding 通过 finding quality gate；
- 有 Top 3 高杠杆动作和依赖顺序；
- 区分当前工作区问题与 `HEAD` 基线问题。

### 代码验收

- `npm test` 真正执行所有测试并退出 0；
- `npm run typecheck` 退出 0；
- `npm run build` 退出 0；
- 新增回归测试在修复前能证明失败场景，在修复后通过；
- 浏览器 smoke 无未处理 console error；
- 下载 MIME/扩展名、结果 stale、批次竞态和 URL 回收有自动化覆盖；
- 没有破坏或移除审计前用户工作。

## 8. 退出条件

本轮在以下条件满足后结束：

1. 深度审查完成并合并重复 findings；
2. 审查确认的 P0 被测试驱动修复；
3. P1/P2 形成后续任务，不在同一轮无限扩张；
4. 全量验证通过，或明确记录无法在本轮解决的 blocker；
5. `handoff.md` 与稳定化文档同步最终事实。
