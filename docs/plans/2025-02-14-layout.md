# FilmFrame 前端重构：信息架构与响应式布局计划

> 计划日期：2025-02-14  
> 原始规格：[SPEC.md](2025-02-14-frontend-redesign/SPEC.md)  
> 配套计划：[设计系统](2025-02-14-design-system.md)、[路线图](2025-02-14-roadmap.md)、[QA](2025-02-14-qa.md)  
> 实施状态：已于 2026-07-12 落地；本文保留布局合同和响应式验收标准。

## 1. 布局目标

把当前“左侧设置栏 + 右侧工作室”的后台式结构改成稳定的数字暗房工作台：全局 Header 承担会话与导入/导出，Workspace 承担图像和输出模式，Recipe Inspector 承担参数，移动端用 Sheet 与底部动作栏承载同一套操作。

布局重排必须保留当前业务事实：单页无路由；图片数组顺序决定帧号、长条顺序和 ZIP 顺序；设置通过现有 `FilmSettings` 与 localStorage service 持久化；处理、stale、Worker、预览、裁切和下载仍由既有 service/callback 驱动。

## 2. 现状到目标

| 现状（源码证据） | 目标结构 | 迁移约束 |
| --- | --- | --- |
| `App.tsx` 1127 行起输出整页 JSX，左侧 `aside` 与右侧 `main` | `AppShell > AppHeader + app-body > Workspace + RecipeInspector` | 先保留 App controller，展示组件通过 typed props 接入 |
| 输出模式 toggle 位于 sidebar | Workspace 顶部 `tablist`/`aria-pressed` | 切换不得清空图片、设置或已完成结果 |
| 添加/导出在工作区 header，社区/捐赠在 sidebar | 添加/导出进入 Header；更多菜单承载 GitHub/支持/重置 | Header、Inspector、底栏不得竞争主 CTA |
| 移动设置作为页面尾部展开 | 固定底部 `MobileSettingsSheet` | Sheet 打开时锁背景滚动，底部栏隐藏或 inert |
| Contact Sheet、Film Strip、Preview、Error、Donate 共享单体 JSX | 按 feature 拆分纯展示组件 | 保留 dialog 焦点优先级与 URL 生命周期 |

## 3. 语义 DOM 与区域职责

```tsx
<AppShell>
  <AppHeader />
  <div className="app-body">
    <main id="workspace">
      <WorkspaceToolbar />
      <WorkspaceContent />
    </main>
    <RecipeInspector />
  </div>
  <MobileActionBar />
  <MobileSettingsSheet />
  <PreviewDialog />
  <FeedbackLayer />
</AppShell>
```

区域职责：

- `AppHeader`：Logo、会话摘要、添加照片、条件导出、更多菜单；手机只保留紧凑品牌、摘要和设置入口。
- `WorkspaceToolbar`：eyebrow、标题、状态摘要、单张/长条 Tab、局部添加/导出动作。
- `WorkspaceContent`：空态、Contact Sheet、Film Strip 三选一；不复制状态判断。
- `RecipeInspector`：当前配方摘要、胶片/影像/输出/配方 sections 和 sticky CTA。
- `MobileActionBar`：手机唯一常驻主操作；Sheet 打开时隐藏或 inert，避免重复 CTA。
- `MobileSettingsSheet`：手机/大手机的胶片、输出、配方三 Tab；固定 header/body/footer。
- `PreviewDialog`、`CropEditor`、`FeedbackLayer`：独立覆盖层，各自只允许一个 active focus trap。

## 4. 断点与尺寸合同

| 宽度 | 布局 | 关键尺寸与行为 |
| --- | --- | --- |
| `< 640px` | 手机单列 | Header 约 56px；Workspace padding 12–16px；固定底栏至少 64px + safe-area；设置为全宽底部 Sheet |
| `640–767px` | 大手机 | 单列或条件双列；设置仍为 Sheet；所有操作目标至少 44×44px |
| `768–1179px` | 平板/小桌面 | Workspace 全宽；Inspector 默认关闭，右侧 Drawer `min(380px, 92vw)`；卡片两列 |
| `>= 1180px` | 桌面 | Header 64px sticky；`grid-template-columns: minmax(0, 1fr) 344px`；Inspector sticky，`top: 64px`，高度 `calc(100dvh - 64px)` |
| `>= 1536px` | 大桌面 | Inspector 368px；可用空间足够时 Contact Sheet 最多四列；工作区最大内容宽度约 1500px |

桌面工作区使用页面主滚动，不再制造不必要的嵌套纵向滚动；Inspector 自身可滚动，底部 CTA 固定在 Inspector 内。1440px 宽度下工作区在扣除 Inspector 后仍至少容纳三张合理宽度卡片。

## 5. Header 与 Workspace Toolbar

### 5.1 Header

桌面左侧显示 FilmFrame Logo、品牌名和 `LOCAL DIGITAL DARKROOM`；中部显示 `ROLL 01 / N FRAMES / LOCAL ONLY`，无图片时为 `NEW ROLL / LOCAL ONLY`。右侧按条件显示：

1. `添加照片`，沿用当前上传 gate；
2. 有有效 artifact 时显示 `导出成片`，调用唯一的 ZIP/长条下载 callback；
3. `更多`菜单，包含重置设置、GitHub、支持 FilmFrame、隐私说明。

手机 Header 只显示紧凑 Logo、`N 张 · 本地处理` 和设置按钮；添加与导出由 Workspace/底栏承担。

### 5.2 Workspace Toolbar

从上到下：

1. eyebrow：`CONTACT SHEET` 或 `FILM STRIP`；
2. 标题：`接触印样` 或 `连底长条`；
3. 一句状态说明；
4. 两个工作区 Tab；
5. 条件动作：添加照片，有结果时可显示导出。

Tab 使用标准 `tablist/tab` 或 button + `aria-pressed`，显示数量/状态摘要，例如 `单张成片 · 4`。处理或导出时沿用现有禁用策略，不丢图片、设置或单张结果。

## 6. Workspace 内容

### 6.1 EmptyDarkroom

空态用内联 SVG/CSS 绘制简化未曝光片边、少量齿孔和上传 icon，不使用普通虚线框或大圆形加号。文案固定为：

- 标题：`把这一卷带进暗房`
- 正文：`添加 JPG、PNG 或 WebP。照片只在当前浏览器中处理，关闭或刷新页面后不会保留。`
- 主按钮：`选择照片`
- 次级说明：`也可以把照片拖到工作区`
- 三步：`01 选片 · 02 配方 · 03 冲洗与导出`

Workspace 全区域保留拖放；drag active 显示 `松开以加入这一卷`。真实 file input 仍限制 JPEG/PNG/WebP，混合文件的 warning/error 继续由现有上传服务处理。

### 6.2 ContactSheet

使用 `<ol>` 表达业务顺序，子项为 `<li><PhotoCard /></li>`。网格规则：`<640` 一列，`640–1023` 两列，`1024–1535` 三列，`>=1536` 最多四列，并根据 Inspector 后实际宽度微调。卡片窗口固定 3:2 或 4:3，`object-contain`，横竖方图不能改变卡片高度。

`PhotoCard` 结构：

```text
FRAME 01 / 04                         [状态印章]
                图像窗口
[查看] [下载] [重试] [删除]
文件名 · 日期                         [上移] [下移]
```

图片区不加 opacity、filter 或大面积黑色 hover 覆盖。触屏始终显示必要操作；桌面 hover 与 Tab focus 显示操作。Frame number 必须来自 `frameNumberForIndex()`，不能在组件内重新计算。

卡片状态由 `deriveImageWorkflowStatus` 映射为 `待冲洗 / 需重洗 / 排队中 / 冲洗中 / 已出片 / 冲洗失败`。失败且保留 current artifact 仍可下载；stale 不显示下载伪入口。查看、下载、重试、删除、上移/下移、桌面拖拽和插入 marker 全部保留。

### 6.3 FilmStripWorkspace

中央 Stage 展示未生成、生成中、current、stale 四种状态；已生成图像在中性深色 light table 上 `object-contain`，允许横向滚动。下方或邻近位置是 Sequence Rail：缩略图、序号、文件名 tooltip、删除、上移/下移和桌面拖拽插入 marker。图片数组、顺序或设置变化后旧长条立即显示 `需重新生成`，不得继续标记 current。

Rail 的视觉齿孔 motif 只作装饰，touch 排序以按钮为等价操作。Stage 工具条提供预览、下载、重新生成；Header 和手机底栏在有 current 长条时切换为下载。

## 7. Recipe Inspector 与移动 Sheet

### 7.1 桌面 Inspector

```text
[暗房配方]                         [重置]
[当前配方摘要]
胶片与片边
影像质感
输出
我的暗房配方
----------------------------------
[4 张待冲洗 · JPG · 快速预览]
[开始冲洗 / 停止后续]
```

前三个 section 默认展开，配方 section 默认收起但有已选配方时展开。摘要卡显示胶片名、`REAL 135 · NATIVE · JPG 95` 等当前值和窄品牌色条；非 Gold 200 明确标注 `CLASSIC REBATE`。所有 `FilmSettings` 字段、Gold 200 real135 门控、classic 片边定制、JPG/PNG 条件、配方 12 条/40 字/同名覆盖规则均沿用现有 service。

Footer 主标签由 `getPrimaryAction` 和 pending/exporting 状态推导：无图添加、待处理冲洗、processing 停止后续、长条生成/重生成、全部最新禁用。已有单张结果可提供次级“重新冲洗全部”。processing 时 CTA 为中性/safelight，不使用 amber。

### 7.2 平板 Drawer

Header 的“配方”打开右侧 Drawer，宽度 `min(380px, 92vw)`；使用 `role="dialog"`、`aria-modal="true"`、焦点闭环、Escape 关闭、焦点恢复。Drawer footer 与 Header 之间只保留一个当前主操作。

### 7.3 手机 Sheet

Sheet 高度 `min(92dvh, 760px)`，固定 Header、可滚动 Body、固定 Footer。内部 Tab 为 `胶片 / 输出 / 配方`，不叠加长列表 accordion。打开时背景锁滚动，Body 使用 `overscroll-behavior: contain`；processing 时背景点击不能误触停止。Sheet 打开期间页面底部栏隐藏或 inert，关闭后恢复触发按钮焦点。

## 8. Preview、Crop 与反馈层

### 8.1 Preview

Preview 是全屏暗房审片台：顶部显示帧号/文件名/序号和分享、下载、关闭；中央是无纹理 image stage；边缘有上一张/下一张；底部控制条提供原图/成片、调整构图、旋转、应用并冲洗此张。控制条不得遮挡图片，按钮目标至少 44px。保留 Escape、左右循环导航、关闭后的焦点恢复、source mode 重置和 current artifact 下载条件。

手机 Preview 顶部紧凑，底部控制分两行或横向滚动，不引入额外 swipe 手势。

### 8.2 Crop

继续使用现有 `components/CropEditor.tsx` 与 `services/renderTransform.ts` 语义：固定片窗、pan、100%–300% zoom、指针锚定 wheel、方向键/Shift、90°旋转、reset、cancel、done；昂贵渲染只在提交后发生。视觉使用暖黑 matte、paper 片窗边界和低对比三分线。Desktop 片窗最大约 1180px、控制条 900px；mobile 使用 `100dvh` 和 safe-area，控制条不覆盖片窗。

### 8.3 Feedback/Dialog

Toast 位于 desktop Header 下方右上、mobile 顶部居中，最大宽度 420px，4 秒自动离开且可手动关闭。Error Dialog 使用暗色 `需要处理` 标题、文件级错误和可行动建议。Support Dialog 移入 More 菜单，`/alipay.jpg` 失败时显示明确 fallback，不显示 broken image，也不伪造 QR。

## 9. 组件与数据流映射

建议的 feature 目录：

```text
components/
  app/{AppShell,AppHeader,MoreMenu,SessionMeter}.tsx
  ui/{Button,IconButton,SegmentedControl,Field,RangeField,StatusStamp,
      Disclosure,ModalSurface,Sheet}.tsx
  icons/FilmFrameIcons.tsx
  workspace/{Workspace,WorkspaceToolbar,EmptyDarkroom,ContactSheet,
      PhotoCard,PhotoCardActions,FilmStripWorkspace,FilmSequenceRail}.tsx
  settings/{RecipeInspector,RecipeSummaryCard,FilmSettingsSection,
      LookSettingsSection,ClassicRebateSettings,OutputSettingsSection,
      RecipeManager,MobileSettingsSheet}.tsx
  preview/{PreviewDialog,PreviewHeader,PreviewControls,CropEditor}.tsx
  feedback/{NoticeToast,ErrorDialog,SupportDialog}.tsx
  mobile/MobileActionBar.tsx
```

`App.tsx` 继续保留状态、derived view model、业务 callback 和编排；组件 props 必须显式 typed。建议按以下边界传递：

- Header：文件输入、添加、导出、重置、更多菜单。
- Workspace/PhotoCard：图片、状态、artifact、active/queued、查看/下载/重试/删除/移动/拖拽 callback。
- Inspector/Sheet：settings、recipes、pending count、CTA、设置变更和配方 callback。
- Preview/Crop：preview source、导航、分享、下载、transform callback。
- Feedback：notice、error、support 状态和关闭 callback。

不要复制 `images` 作为第二个顺序源；不要在展示组件中复制 render key、stale、generation 或下载判断。

## 10. 响应式验收矩阵

| 尺寸 | 必须确认 |
| --- | --- |
| 360×800 | 空态首屏、底栏、Sheet footer、Preview/Crop 不横溢 |
| 390×844 | 品牌/隐私/上传可见；Sheet 无遮挡；44px 目标；底栏安全区 |
| 768×1024 | Drawer 打开关闭、焦点恢复、两列卡片、无重复 CTA |
| 1024×768 | Workspace 全宽、Inspector Drawer、Strip rail 横向滚动 |
| 1440×1000 | Header sticky、三列卡片、344px Inspector、主流程可见 |
| 1536×864 | 最多四列、368px Inspector、Preview/Crop 控件不盖图 |
| 2560×1440 | 内容不被过度拉伸，图片仍为视觉中心，背景纹理克制 |

所有尺寸都需覆盖空态、1/4/20 张、混合方向、六种 workflow 状态、长文件名、12 条配方、Preview、Crop、Strip current/stale 和 200% 缩放。

## 11. 布局完成门槛

- [ ] Header、Workspace、Inspector/Drawer/Sheet、底栏职责清晰，主 CTA 无重复竞争。
- [ ] 输出模式成为 Workspace 级 Tab，不再是设置字段。
- [ ] 桌面图像在左、参数在右；手机设置不再形成页面尾部长表单。
- [ ] Empty、Contact Sheet、Film Strip、Preview、Crop、Error、Support 均使用统一 Modal/状态语义。
- [ ] 键盘、触屏、拖拽和上移/下移都能完成排序与关键操作。
- [ ] 390×844、1440×1000 无横向溢出、遮挡或焦点丢失。
- [ ] 组件化后继续使用既有 render/download/storage/workflow service，现有测试全部通过。

## 12. 实施证据

- 桌面 `>=1180px`：Workspace + 344px sticky Inspector；1440×1000 截图已验证。
- 平板 `768–1179px`：Header 打开右侧 Drawer，Escape 后焦点回到触发按钮。
- 手机 `<768px`：紧凑 Header、固定动作栏、底部 Sheet；Sheet 打开期间底栏保持 inert，关闭后焦点恢复。
- 390×844 与 1440×1000 检查 `scrollWidth === innerWidth`；最终截图位于 `output/playwright/final-redesign-*.png`。
