# Technical Design: Complete Process And Export

## Decision Boundary

从 `App.tsx` 提取一个纯导出决策函数，以“已选中照片”和“当前设置对应的有效成片”为输入，返回总数、有效数、待处理 ID，以及 `complete / incomplete / empty` 状态。它只计算，不读写 React 状态或下载文件，便于穷举测试。

## User Flow

- `complete`：沿用现有 ZIP 打包下载。
- `incomplete` 且至少有一个有效结果：打开确认对话框，主操作“冲洗剩余照片并导出”，次操作“仅导出当前 N/M 张”。
- `incomplete` 且没有有效结果：对话框只提供“冲洗全部并导出”。
- 补齐处理中沿用现有进度和停止入口；成功后基于最新 refs 再计算一次完整性，只有全部有效才下载。
- 失败或停止仅结束待导出意图，不触发下载。

确认对话框复用现有 `ModalSurface` 和按钮组件，聚焦取消按钮并在关闭后恢复到 ZIP 触发器。对话框只接收统计与命令，不拥有渲染或导出资源。

## State And Async Contract

`App.tsx` 增加最小的导出意图状态，用于区分普通批处理和“补齐后导出”。补齐命令复用同一批处理执行函数，并传入由纯决策函数得到的待处理 ID。批处理完成后必须再次校验：

1. 当前渲染 generation 未失效；
2. 用户没有停止；
3. 所有当前选中照片都有与当前设置匹配的结果。

任何条件不满足都不下载。已有有效结果继续复用，下载仍由现有 ZIP 函数完成。

## Compatibility And Rollback

无持久化格式、渲染器或文件格式变化。回滚只需移除纯决策 helper、对话框和补齐后导出意图，恢复 ZIP 按钮直接调用原下载逻辑。

## Testing

- 纯函数测试：完整、部分、零结果、未选中照片、失效 render key。
- 浏览器测试：`3/4` 时补齐后导出、仅导出 `3/4`、停止/失败不下载、完整时不弹框。
- 既有 ZIP 内容与长条下载测试必须继续通过。
