# Customizable frame number color

## Goal

Allow users to choose one global color for all dynamically generated frame-number markings, independently from the film stock's other text colors. The chosen color must follow the user across film stocks and render modes without recoloring labels baked into real-135 template artwork.

## Background

- `FilmSettings.frameNumber` already controls the starting number for single and strip output.
- Dynamic real-135 template numbers currently reuse `textColor` in `services/filmFrameNumber.ts`, while continuous Gold strip markings use a hard-coded amber in the main-thread and Worker renderers.
- Classic rendering draws frame numbers with the general `textColor`, so changing a frame number currently also changes unrelated labels.
- Preferences and saved recipes are normalized through `services/settingsStorage.ts`; output freshness is determined by `services/renderResult.ts`.

## Requirements

- Add an optional `frameNumberColor` field to `FilmSettings`, accepting normalized six-digit HEX colors.
- Expose a color swatch beside the existing starting-frame-number control in desktop and mobile recipe settings.
- Keep the selected color global across film-stock changes, single/strip output, and real-135/classic render modes.
- Apply the color only to dynamic frame-number glyphs, including numeric suffixes such as `A` where generated by the application.
- Keep stock names, dates, DX-like blocks, safety-film labels, and other markings on their existing color paths.
- Keep main-thread and Worker output behavior aligned.
- Persist the setting in local preferences and saved recipes, and include it in render identity so existing artifacts become stale after a color change.
- When no explicit color is selected, preserve each renderer's current effective frame-number color; an explicit user selection becomes the global override.
- Reset restores the default/fallback behavior.

## Acceptance Criteria

- [x] A user can select a frame-number color from the recipe inspector on desktop and mobile.
- [x] Selecting a color changes dynamic frame numbers in real-135 single output and real-135 strip output for every supported stock.
- [x] The same color changes generated frame numbers in classic single and classic strip output without changing unrelated text.
- [x] Gold 200 Worker rendering and main-thread fallback render frame numbers with the same selected color.
- [x] Switching film stocks does not reset an explicitly selected frame-number color.
- [x] Valid `#RRGGBB` values survive preference and recipe round trips; invalid stored values are ignored.
- [x] Changing only `frameNumberColor` marks single and strip artifacts stale.
- [x] Existing settings without `frameNumberColor` retain each renderer's current effective frame-number color.
- [x] Focused unit tests and a browser workflow cover selection, persistence, render identity, and representative main-thread/Worker output paths.
- [x] `npm run check`, `npm run test:e2e`, and `git diff --check` pass.

## Out of Scope

- Recoloring frame numbers or labels already baked into PNG film-template artwork.
- Per-photo or per-film-stock frame-number colors.
- Changing frame-number typography, placement, numbering, or suffix rules.
- Adding another color-picker implementation; use the project's existing color-control conventions.
