# 重规划数字暗房工作区

## Goal

让摄影爱好者无需理解渲染实现细节，也能通过「选片 → 调整 → 出片」完成 135 胶片效果制作。统一任务路径、中文功能名称与视觉层级，重点重构空暗房「让这一卷，慢慢显影」，同时保留现有本地渲染和交付能力。

## Background

- 当前空状态把照片选择、摄影名言、三步流程和整幅胶片背景分散在约 580px 高容器中，主操作和照片主题不够突出；用户提供元素 `main#workspace` 内 `.ff-empty-darkroom`。
- 工作区把「接触印象」「连底长条」等模式名称与「物理底片」「真实 135 贴图」「经典片边」「光谱负片」「扫描输出」等实现术语同时展示，缺少面向任务的层级。
- 现有页面为桌面右侧设置栏、平板侧边抽屉、手机底部设置与操作栏，见 `App.tsx:1501-1649`、`components/app/AppShell.tsx`、`components/workspace/WorkspaceToolbar.tsx`、`components/settings/RecipeInspector.tsx`。
- 现有空暗房有连续胶片动画和本地审核摄影名言，动画、画幅、减弱动态及引用规则见 `.trellis/spec/frontend/quality-guidelines.md`。
- 工作区有大量未提交的渲染、发布及测试修改；本任务必须保留这些修改，不回滚、不覆盖、不纳入无关变更。

## Confirmed Decisions

- 主要用户：希望快速得到可信胶片效果、理解胶片型号但不需要先学习渲染术语的摄影爱好者。
- 主流程：统一为「选片 → 调整 → 出片」。单张与胶片长条属于出片方式，高级渲染参数渐进披露。
- 项目流程：使用 Trellis 完整记录需求、设计与实施计划；用户审阅方案并再次批准后，才能修改产品代码。
- 方向：工作区布局与视觉系统重规划，不只是修改空状态配色。具体视觉方向由设计评审确认。

## Requirements

### R1 主任务路径

- 工作区以「选片、调整、出片」建立清晰层级，同一时刻只有一个主要行动。
- 空状态首屏直接说明照片生成 135 胶片效果的核心价值，并让「选择照片」成为最突出且可键盘操作的动作。
- 空状态保留拖放、连续 135 胶片及本地审核摄影名言，但降低装饰与次要信息对主操作的竞争。
- 有照片后以照片预览为主；选片数量、已出片与待处理状态清楚可见，单张和长条使用一致的「出片」语言。

### R2 命名与渐进披露

- 顶级导航和主要操作采用面向任务的中文，不以内部技术模式命名工作区。
- 保留真实胶片型号；将「成像方式、片边、输出」组织为可理解的分组，将计算后端等工程术语置于高级设置。
- 不隐藏用户完成现有任务所需的功能；高级选项仅在相关模式或主动展开时出现。
- 组件及数据层的英文工程标识不重命名，仅调整用户可见命名和必要的展示结构。

### R3 一致的视觉系统

- 保留 FilmFrame 名称与数字暗房身份，建立一个克制、有摄影内容主导权、不同于当前均等深色面板的完整方向。
- 统一标题、正文、辅助标注、间距、边框、按钮、状态、选中、焦点、错误及移动端的视觉规则。
- 不使用表情符号作为图标，不引入无功能装饰、虚构指标或无关营销模块。
- 保留现有真实照片、胶片素材与审核引语，不用占位图代替实际成像能力。

### R4 行为与可访问性

- 保留 JPG、PNG、WebP、HEIC/HEIF 导入、拖放、照片排序与入选、构图、预览、配方、单张与长条渲染、下载、ZIP 导出及错误恢复。
- 保留本地处理隐私边界，不添加照片上传、遥测或第三方运行时图像处理。
- 保留减弱动态、动画暂停、键盘标签操作、对话框焦点管理、至少 44px 触控目标和可辨识文本对比度。
- 适配桌面、平板和 390px 手机，不出现横向溢出、主操作遮挡或不可达设置。

### R5 工程边界

- 优先复用 `App.tsx` 的状态和工作流，将变更集中在 `components/app`、`components/workspace`、`components/settings`、`components/mobile` 与 `styles`。
- 不修改渲染算法、Worker 协议、胶片数据、访问控制、部署及发布文件。
- 与现有未提交修改相交的文件采用局部编辑，不执行 destructive Git 操作，不擅自提交或部署。

## Acceptance Criteria

- [x] AC1：空状态在 1440px、1180px、768px、390px 视口完整呈现，主标题、胶片视觉、选择照片按钮和隐私提示形成明确层级；无横向溢出。
- [x] AC2：用户可在首屏理解「本地照片 → 135 胶片效果」及「选片 → 调整 → 出片」；主按钮在同一工作区中不与多个同权重操作竞争。
- [x] AC3：单张与长条统一归入出片路径，摄影爱好者常用设置直接可达，工程后端等高级参数按需展开，既有渲染能力未删除。
- [x] AC4：实际浏览器完成选片、模式切换、配方调整、预览、冲洗与导出相关回归；既有操作的可访问名称或测试同步维护，不以隐藏功能通过测试。
- [x] AC5：键盘、减弱动态、空状态拖放、手机设置面板及对话框焦点恢复正常，触控目标满足项目约定。
- [x] AC6：桌面、平板和 390px 手机截图经过视觉审查；运行 Impeccable 检测、独立 finish review，并记录最终视觉系统。
- [x] AC7：运行与改动相关 Vitest 和 Playwright 测试、`npm run typecheck`、生产构建及 `git diff --check`，如实报告失败及未验证项。
- [x] AC8：渲染、发布与本任务之外的已有工作区修改保持原样；没有未授权提交、推送或部署。

## Out of Scope

- 改变胶片成像结果、光谱数据、物理 135 算法、渲染预算与 Worker 路由。
- 新增账户、云同步、社交分享服务、付费功能、教学网站或营销落地页。
- 全局重写状态管理、更换框架、引入新 UI 组件库或为视觉改版重命名所有工程文件。
- 处理已有无关测试失败或发布遗留项；仅区分并报告其影响。
