# 「胶片索引」独立视觉审查

## 结论

方向成立，但不能把 `assigned.html` 当成可直接套用的桌面海报。应把胶片从空状态背景改为解释工作结果的主角：左侧明确导入，右侧用有出处的照片示意解释 135 画幅；选入照片后，同一位置直接成为真实照片工作台。冷灰蓝、石灰白、氧化橙可以建立新识别，但成功取决于减少操作、收起空状态高级参数，以及让连续胶片服从内容，而不取决于换色或放大标题。

本审查只针对视觉、信息层级与 Operate 交互；未改产品代码，未改变渲染、设置值或工作流。

## 证据与边界

- 在独立标签实测 `http://127.0.0.1:5174/` 的空状态：桌面 `1440 × 900`，手机 `390 × 844`。未操作用户原有页面。
- 桌面页头高 65px，工作区工具栏从 y=65 延伸至 y=282；空暗房到 y=282 才开始。手机工具栏占 253px，空暗房到 y=326 才开始。
- 手机同时可见工具栏「添加照片」、空暗房「选择照片」和底部固定「添加照片」三个同义入口。空暗房主按钮上缘约为 y=476；固定底栏从 y=780 开始，覆盖名言出处与底部流程。
- 桌面右侧 344px 配方栏在空状态即显示成像方式、光谱计算、物理底片及后续参数，视觉密度超过导入区。
- 已读 `PRODUCT.md`、方向契约、审查简报、已选方向、空暗房、页头、样式与指定 E2E 前 190 行；另核对 `App.tsx:1449-1633`、`WorkspaceToolbar.tsx`、`MobileActionBar.tsx` 和 `services/photographyQuotes.ts`，用于确认操作归属与动态行为。

## 1. 当前首屏的核心视觉问题

按影响排序：

1. **没有照片结果，只有技术容器。** 满幅 332px 高空胶片是背景，16 个画幅没有照片，也没有说明照片如何进入 135。标题与按钮悬在空片上，像尚未加载的工作区，而非可理解的导入工具。见 `EmptyDarkroom.tsx:45-80`、`styles/components.css:708-800`。
2. **主任务被同权重操作稀释。** 桌面已有页头、工具栏两个添加入口和配方栏底部「先添加图片」；手机同屏出现三个入口。用户能看到很多操作，却不能更快判断唯一第一步。见 `AppHeader.tsx:70-100`、`WorkspaceToolbar.tsx:93-113`、`MobileActionBar.tsx:28-55`、`App.tsx:1624-1633`。
3. **页面标题与输出方式争夺层级。** 「接触印象 / CONTACT SHEET」占据主标题，「单张成片 / 连底长条」又在空状态占据大块工具栏；这是专业分类先于选片任务。空状态不需要先决定输出方式。
4. **空状态高级设置比内容更显眼。** 桌面配方栏占据首屏整个右栏，小字号、密集边框与多个技术标签形成仪器墙。摄影爱好者尚未选片，就先面对光谱后端与物理底片，不利于建立可信但易用的第一印象。
5. **手机把桌面区块纵向堆叠，没有重排任务。** 顶部 310px 才被导入区接替；名言卡片和流程又延伸到底栏后面。实测不是横向溢出，而是纵向优先级错误。`WorkspaceToolbar.tsx:74-149` 和 `EmptyDarkroom.tsx:45` 的固定最小高度共同加剧这一问题。
6. **材质在模拟暗房，却削弱信息。** 暖棕、宋体、全局颗粒、暗角、表面高光、细线和小号等宽字同时出现，文字明度被进一步压低。`tokens.css:72-82`、`base.css:38-70`、`components.css:70-110,1247-1287`。当前不是缺少装饰，而是装饰没有层级约束。

## 2. 「胶片索引」应保留、替换与避免的元素

具体约束：

### 390px：标题、画幅、主按钮必须形成一屏任务

采用以下 DOM 与视觉顺序，不用桌面绝对定位拼接：

1. 56px 左右轻量页头，只保留品牌、简短会话状态、更多；空状态不放设置齿轮和添加按钮。
2. 标题与一句说明，左右边距 20px，顶部间距 24px；标题 28–30px，避免大面积空白。
3. 胶片画幅，宽度 `calc(100vw - 40px)`，约 350px；3:2 照片约 233px 高，轨道各 18–22px。相邻画幅可向屏幕边缘延伸，但页面不能产生横向滚动。
4. 画幅下方短标注「照片示意 · 非渲染结果」，随后唯一「选择照片」48px 主按钮；按钮可全宽，也可与拖放 / 隐私说明形成紧凑一组。
5. 摄影名言作为后续正常文档流内容。390×844 下优先让标题、完整画幅、主按钮与隐私都可见；名言可以部分或全部位于首屏下方，不能为塞进首屏而缩小到难读。
6. 空状态隐藏移动固定底栏，避免重复添加和遮挡。有照片后再显示现有底栏，并给页面底部预留其实际高度与 safe-area。

手机不要照搬「标题、画幅、按钮」就结束：必须同时保留按钮附近的本地隐私说明，并避免把说明拆成三行小字。推荐目标为：在 390×844 中，主按钮上缘不晚于约 600px，按钮与隐私在约 700px 前完整出现。具体以真实最长文案、字体缩放和照片比例复核，不设固定总高度。

### 连续胶片、名言与减弱动态

- 延续 `ff-empty-film-transport`、36s、线性、无限的现有测试契约，但让位移等于一个「画幅宽 + 间距」的周期，使用重复内容实现无缝循环；现有轨道只从 `left:-360px` 再平移 `-360px`，而画幅周期为 360px、初始偏移又恰好为 -360px，首尾可见内容并不严格等价，不能称为无缝。见 `components.css:719-735,765-773,1308-1312`。
- 速度应慢到不妨碍阅读，保持 36s 周期即可；运动只作用在胶片轨道，不让标题、按钮、说明或名言移动。
- 保留空暗房整体 `hover`、`focus-within`、拖动时暂停，见 `components.css:1290-1300`。即使只有装饰画幅，也不增加需要精确 hover 的交互。
- `prefers-reduced-motion: reduce` 下完全停用位移动画、取消 `will-change`，显示稳定的完整 3:2 主画幅；不要靠保留 `-180px` 静态偏移来决定手机构图。现有 `components.css:1518-1522` 只证明旧背景静止，新实现需重新断言主画幅位置。
- 名言按现有日期每日更新，无需淡入、逐字、轮播或「换一句」。引用高度由最长审核文案决定，可用最小高度避免每日布局跳动，但不要裁切来源。`photographyQuotes.ts:3,113-125` 已证明它是日轮换，不是动画轮播。
- 保留 `data-testid="empty-darkroom-film-track"`、rail、frame、quote/context 和现有动画命名，更新测试的几何断言；不要为了新视觉删除可访问暂停与减弱动态契约。

## 4. 样式 token 与控件层级

### Token：先改语义，不新增第二套平行系统

`assigned.html` 的候选色可作为首轮 token 值，而非局部硬编码：

| 语义 | 建议起点 | 用途 |
| --- | --- | --- |
| `--ff-bg-deep` | `#12181b` | 页面最底层、胶片空隙 |
| `--ff-bg` | `#171d20` | 石墨蓝工作面 |
| `--ff-panel` | `#20292d` | 轻量配方、drawer、必要控件面 |
| `--ff-panel-raised` | `#273237` | 菜单与对话框，不给每块内容升级 |
| `--ff-paper` | `#e8e7df` | 主文字、标题 |
| `--ff-paper-muted` | `#a7b4b6` | 正文辅助、说明 |
| `--ff-paper-dim` | 实际验证后的中间灰 | 次要 meta，不作为长正文默认色 |
| `--ff-amber` / hover | `#ed9b52` / 稍亮橙 | 仅主操作、当前选中、拖拽目标 |
| `--ff-info` | `#92afb4` | 本地状态、信息与焦点辅助 |
| `--ff-line-soft` / `--ff-line` | 在背景上达到 3:1 的控件边界 | 分隔与输入边界；不能直接用稿中 `#3b4b50` 当所有细线 |

已选稿的可计算起点：`muted/bg` 为 7.99:1、`muted/panel` 为 6.95:1、`ink(#1e2525)/accent` 为 6.99:1；但 `line(#3b4b50)/bg` 只有 1.87:1，不足以单独承担输入控件的非文字边界。线色需调亮，或同时使用足够的形状、填充与状态差异。所有实际组合仍需按最终背景复核 WCAG 对比度。

执行方式：

- 优先更新现有语义 token，并删除组件中依赖暖棕的硬编码渐变、高光和边框色；不要仅把 `--ff-amber` 改名后保留旧棕色 `color-mix`。重点见 `components.css:70-110,191-207,1247-1287`。
- 增加 `--ff-accent-action`、`--ff-accent-action-hover` 等清晰语义，逐步替代把 amber 同时当品牌、警告、处理中、选中和主操作的用法。保留现有危险、警告、停止语义，不能全染成橙。
- `--ff-font-display` 改为现有系统人文无衬线：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Noto Sans SC", sans-serif`；不新增网络字体。`--ff-font-ui` 可复用同一族。等宽只用于数字、格式、帧号、真实型号，不用于品牌副标和流程说明。
- 保留 4 / 8px 间距基础、3–5px 小圆角和现有 44px 触控下限。控件不应为「现代感」变成大圆角胶囊。
- 默认去掉全局 `body::before` 颗粒与 `body::after` 暗角，或至少让它们不覆盖工作区文字与控件。建议正式方向直接移除这两层，而不是继续调低透明度掩盖对比度问题。
- 空胶片画幅颜色必须随新 token 改变；E2E 当前硬编码 `rgba(72, 63, 49, 0.12)`，需更新为新构图与语义，而不是为通过旧测试保留暖色。

### 控件层级：每个视口只有一个主任务

| 状态 | 主操作 | 次操作 | 收纳 |
| --- | --- | --- | --- |
| 空状态桌面 | 内容区「选择照片」 | 配方型号 select、名言来源链接 | 更多菜单；其余调整默认折叠 |
| 空状态手机 | 内容区「选择照片」 | 名言来源 | 更多菜单；隐藏移动固定底栏与重复设置入口 |
| 已选片未出片 | 「开始冲洗」或现有真实处理动作 | 「添加照片」、胶片 / 片边 / 输出 tabs | 高级设置 disclosure、更多菜单 |
| 已有可下载成片 | 一个「导出成片」 | 添加、继续调整 | 历史结果操作不另造主按钮 |
| 处理中 | 明确的「停止后续」 | 状态说明 | 禁用冲突操作，保留真实 busy 状态 |

- 「选片 / 调整 / 出片」是理解路径，不再增加一套可点击导航或路由状态。真正的 tabs 只有有照片后的「单张 / 胶片长条」输出选择。
- 主按钮用实心氧化橙；次按钮用透明 / 面板底加清晰边框；设置、更多为 ghost 或图标按钮。不要让页头每个按钮都有箱体高光，也不要让禁用的「先添加图片」仍呈主按钮色。
- 顶部「添加照片」在空状态隐藏；有照片后可以保留 `AppHeader.tsx:70-79` 的真实 handler 与可访问名称。空暗房主按钮继续使用「选择照片」，与文件输入一致。
- 手机保留现有 `MobileActionBar` 给有照片工作流，空状态不渲染或隐藏它；页头与底栏也不要同时放两个设置齿轮。`App.tsx:1624-1633` 已集中提供该入口，无需新增状态。
- 渐进披露高级设置时，不删除原始 label；测试和使用者仍可找到「成像方式」「底片渲染」「光谱计算」。已有非默认高级值或旧配方恢复时，对应组应自动展开并显示已生效状态。
- 触控目标至少 44px；当前 tabs 外层 44px、内按钮 36px 的结构不能把可视点击区算成达标，应让实际按钮自身达到 44px。

## 5. 此方向在 Operate 工具中的最大风险

**最大风险是把「漂亮的空状态海报」当成工作区重构完成：空态获得大照片与大标题，有照片后仍回到原来的高密控制面板，二者只有颜色相同，任务连续性和操作效率没有改善。**

具体会有三个后果：

1. **认知断层**：空态大画幅承诺照片是主角，导入后却被工具栏、tabs、参数和多个主操作挤回次要位置。
2. **效率倒退**：为了维持海报构图而长期固定右栏、步骤和引言，真实工作时的照片数量、排序、处理状态与导出动作得不到空间。
3. **功能被视觉隐藏**：把高级参数简单删除、改变设置语义或只做空态折叠，会让已有用户找不到真实配置，破坏渲染结果的可信度。

设计验收应优先看同一个视口从空态到多张照片、处理中、可下载、设置变更后的连续表现，而不是只验收一张空态截图。先做操作去重、空 / 工作态共用画幅与右栏分组，再做色彩和材质；顺序反了会得到换皮，而不是「胶片索引」。

## 实施与验收要点

- 以 `EmptyDarkroom`、空状态工具栏分支、配方摘要和 token 为主，不改 `App.tsx` 的 Worker、资源所有权、渲染参数或状态机。
- 更新 `frontend-redesign.spec.ts:53-190` 的旧几何断言：332px 总高、342×228 画幅、52px 轨道和旧背景色都不能继续约束新构图；3:2、轨道存在、动画、暂停、拖动、无横向溢出和 reduced-motion 必须继续验证。
- 最少覆盖桌面 1440×900、手机 390×844、有照片后的工作态，以及最长名言 / 最大合理文本缩放。手机另需验证固定底栏不会覆盖名言、流程或最后一个操作。
- 浏览器实际完成：桌面与 390px 空状态截图、可见布局与宽度检查；未完成：真实移动设备、运行时 reduced-motion 切换、有照片后的新构图。上述项目应在实现后补验。
